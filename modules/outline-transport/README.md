# Транспорт Outline

Нативный необязательный адаптер FlowVPN для Windows x64. Использует закреплённый Outline SDK, принимает аутентифицированный SOCKS5 на `127.0.0.1` и отправляет TCP/UDP через Shadowsocks. TUN, маршруты, системный DNS и настройки прокси не изменяет.

**Статус:** реализация и локальные проверки; работа через настоящий TUN, установленный MSIX и сервер провайдера требует отдельной приёмки. Наличие исходников не означает, что артефакт уже опубликован или доступен для загрузки из приложения.

## Совместимость

- `aes-128-gcm`, `aes-256-gcm`, `chacha20-ietf-poly1305`; SS2022 не поддерживается.
- Prefix применяется только к TCP. Так работают и `ss://`, и плоский legacy JSON в [официальном `parseShadowsocksTransport`](https://github.com/OutlineFoundation/outline-apps/blob/master/client/go/outline/configregistry/config_shadowsocks.go).
- Prefix поступает как канонический Base64 уже декодированных байтов. Преобразование символов U+0000–U+00FF в байты выполняет FlowVPN. Предел — 8 байт для AES-128-GCM и 16 для двух остальных методов: остаётся не менее восьми случайных байт соли. Это ограничение адаптера; длинные значения отклоняются, не обрезаются.
- Имя целевого SOCKS-сервиса передаётся внутри Shadowsocks без локального DNS. Адрес самого Shadowsocks-сервера FlowVPN заранее разрешает в IP до включения TUN.

## Контракт IPC v1

Запуск без аргументов и без повышения прав. `--version` только выводит версию и не открывает сокеты.

В stdin передаётся **одна UTF-8 JSON-строка с завершающим LF** размером до 1 МиБ. Все поля обязательны; повторные, неизвестные, отличающиеся регистром поля и `null` отклоняются:

| Поле | Значение |
| --- | --- |
| `protocolVersion` | `1` |
| `server` | IP без URL, имени хоста и zone ID |
| `serverPort` | `1..65535` |
| `method` / `password` | Поддерживаемый метод и непрозрачный пароль, до 256 КиБ UTF-8 |
| `prefixBase64` | Канонический Base64 TCP-prefix; пустая строка допустима |
| `interfaceIndex` | Ненулевой индекс физического интерфейса для семейства IP сервера |
| `socksUsername` / `socksPassword` | Новые случайные секреты сеанса, 1–128 печатных ASCII-байт без пробела |

После занятия порта stdout выдаёт единственную строку `{"protocolVersion":1,"port":N}`. Родитель держит stdin открытым: EOF, ошибка канала или любые дальнейшие данные завершают сеанс. Начальная конфигурация ожидается не более 10 секунд, остановка — до 5 секунд. Родитель дополнительно владеет процессом через Job Object и ждёт его завершения. Секреты не передаются через аргументы, окружение и журналы; stderr содержит только краткую общую причину отказа.

## Границы безопасности

TCP/UDP слушают только IPv4 loopback. Анонимный SOCKS запрещён, credentials сравниваются через хеши постоянного размера. Не более 256 одновременных клиентских сеансов; handshake ограничен 10 секундами, UDP-простой — двумя минутами, TCP-простой — десятью. SOCKS BIND и фрагментация UDP не поддерживаются.

У каждой UDP association отдельный порт и аутентифицированное TCP-соединение. Windows IP Helper связывает TCP-клиента и UDP endpoint по PID; проверка выполняется для каждого UDP-пакета в обе стороны, а endpoint после первого допустимого пакета не меняется. Это дополнительная защита локального SOCKS UDP, который сам не содержит credentials в каждой датаграмме; она не является криптографической аутентификацией пакетов. Закрытие управляющего TCP закрывает UDP-сеанс.

Исходящие сокеты привязаны через [IP_UNICAST_IF](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options) и [IPV6_UNICAST_IF](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ipv6-socket-options). Индекс IPv4 передаётся в сетевом порядке байтов, IPv6 — в порядке хоста. Ошибка привязки не включает запасной прямой маршрут.

## Сборка и тестирование

Нужен Go из `toolchain.lock.json`; архив и SHA-256 закреплены, системная установка необязательна. `go.mod` и `go.sum` фиксируют зависимости. Скрипт не загружает и не устанавливает сам Go:

```powershell
./Build.ps1 -GoExe C:/path/to/go/bin/go.exe
```

Скрипт выполняет `go mod verify`, `go vet`, локальные тесты и воспроизводимую сборку с `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`, `-s -w -buildid=`. Результат — `work/outline-artifacts` в корне репозитория; `artifact.json` содержит фактические размер и SHA-256. Это отчёт сборки, а не самостоятельный доверенный манифест для загрузчика. Публикуемые хеши должны попасть в каталог подписанного MSIX.

Для проверки через настоящий закреплённый sing-box:

```powershell
./Build.ps1 -GoExe C:/path/to/go/bin/go.exe -SingBoxPath ../../outputs/FlowVPN/core/sing-box.exe
```

Тест проверяет хеш движка по `engine.lock.json` и запускает цепочку sing-box → адаптер → локальный сервер. Конфигурация не содержит TUN, DNS или API. Тестовый сервер только расшифровывает и отражает данные, не обращается к указанным целевым адресам. Прочие проверки покрывают три шифра, байты prefix, авторизацию, чужой процесс UDP, ограничение endpoint и завершение по EOF.
