# Ресурсы и измерения транспортного модуля

У модуля ограничено число одновременных SOCKS-сеансов: 256, включая TCP и UDP.
Неавторизованное соединение занимает слот не более 10 секунд. Предельный UDP payload —
15 872 байта; это ограничение адаптера, а не обещание поддержки UDP-пакетов любого размера.
UDP-сеанс закрывается после двух минут бездействия. Обычный TCP read idle timeout —
10 минут; после завершения одной стороны оставшаяся передача имеет общий предел
10 секунд, который новые порции ответа не продлевают.

UDP SOCKS5 не содержит отдельной аутентификации каждой датаграммы. Поэтому адаптер
проверяет через Windows IP Helper, что локальный UDP endpoint принадлежит процессу
авторизованного TCP-соединения. Проверка выполняется для каждого входящего и исходящего
пакета; решения о владельце не кэшируются по времени. Полный снимок таблицы Windows и
его просмотр остаются операцией O(N) по количеству системных UDP endpoints.

Для таблиц TCP и UDP используются два повторно заполняемых буфера, каждый не больше
8 МиБ. Этот предел относится к двум общим буферам процесса, а не к каждому сеансу.
При росте таблицы допускаются до трёх попыток получения снимка; слишком большая или
некорректная таблица означает отказ проверки владельца. Доступ к каждому буферу
сериализован, поэтому очередной пакет не может читать перезаписываемый снимок.
Выходной UDP packet buffer также переиспользуется внутри сеанса.

## Локальный benchmark

Измерено 7 ноября 2026 года: Windows x64, Intel Core i9-14900HX, Go 1.27.3.
Контрольный прогон после обновления зависимостей, по одной секунде на сценарий:
отдельно создавались 32, 256 и 1024 собственных
loopback UDP-порта в дополнение к уже открытым системным портам. Пакеты не отправлялись.

| Дополнительные порты | Проверка владельца | Проверок в секунду | Общий UDP buffer | Go heap allocation за проверку |
| --- | ---: | ---: | ---: | ---: |
| 32 | 48,2 мкс | 20,7 тыс. | 4 КиБ | 0 байт / 0 аллокаций |
| 256 | 96,3 мкс | 10,4 тыс. | 8 КиБ | 0 байт / 0 аллокаций |
| 1024 | 290,0 мкс | 3,45 тыс. | 16 КиБ | 0 байт / 0 аллокаций |

Это стоимость одной проверки владельца, а не пропускная способность VPN. UDP-запрос
с ответом требует двух таких проверок; шифрование, системная сеть и передача данных
в эти цифры не входят. При большом числе системных сокетов эта защита может ограничивать
UDP throughput. Измерение не подтверждает производительность на других компьютерах и
не заменяет проверку реального соединения с TUN.

Команда из каталога модуля:

```powershell
go test -mod=readonly -run '^$' -bench '^BenchmarkUDPOwnershipNative$' -benchmem -benchtime=1s -count=2 -timeout 60s ./...
```

В регрессионных тестах отдельно проверяются нулевые аллокации установившегося ownership
пути и неизменность общего half-close deadline после нескольких порций ответа.
CI не устанавливает порог времени по этому benchmark: скорость общего GitHub runner
зависит от нагрузки и не является воспроизводимой аппаратной характеристикой.
