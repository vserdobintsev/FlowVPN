# Замена и восстановление сертификата FlowVPN

FlowVPN использует собственный сертификат. Централизованного автоматического отзыва у этой схемы нет: удаление CER из GitHub, замена PFX Secrets или смена пароля не убирают доверие на уже настроенных компьютерах. Доверие старому сертификату удаляется на каждом ПК отдельно. Эта инструкция не меняет сертификаты сама; автоматическая ротация в приложении не реализована.

## Если ключ потерян

Сначала восстановите **тот же PFX и его пароль** из защищённой резервной копии. Публичный CER не содержит закрытого ключа и восстановить его не позволяет. Файл `password.dpapi` привязан к Windows-учётной записи; он не заменяет независимую резервную копию пароля. GitHub Secrets также не должны быть единственным хранилищем восстановления.

Если резервной копии нет, создайте новую пару ключ/сертификат. Сохраняйте точные значения MSIX `Name="FlowVPN"` и `Publisher="CN=FlowVPN"`; Subject нового сертификата должен быть `CN=FlowVPN`. Версию пакета необходимо увеличить. Семейство пакета определяется именем и издателем, поэтому смена самого ключа при сохранении этих значений не требует смены семейства приложения. Это следует из [модели Package Identity](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/package-identity-overview) и [правил соответствия сертификата манифесту](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing).

## Плановая замена без признаков компрометации

1. Создайте новый сертификат и защищённую резервную копию PFX/пароля. Обновите `Assets/FlowVPN.cer`, GitHub Secrets `PFX_BASE64`/`PFX_PASSWORD`, закреплённый SHA-256 в установщике/CMD и документации. Не меняйте Name/Publisher; увеличьте версию.
2. Соберите выпуск, проверьте подпись и временную метку, затем испытайте обновление поверх предыдущего MSIX на тестовой Windows. Перед испытанием сохраните резервную копию личных данных.
3. Опубликуйте новый отпечаток сертификата через проверяемый канал. Пользователь устанавливает доверие **новому** сертификату с явным согласием и UAC, затем устанавливает новый MSIX.
4. После успешного обновления удалите доверие **старому** сертификату по его точному SHA-256. Порядок: добавить новый → установить обновление → убрать старый. Удаление доверия влияет на всех пользователей ПК, когда сертификат находится в `LocalMachine/TrustedPeople`. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing).

Новый сертификат не становится доверенным только потому, что у него тот же `CN`. Переход требует нового явного доверия. Последующие обновления, подписанные этим сертификатом, не требуют повторять процедуру.

## Если ключ скомпрометирован

Плановый порядок здесь не подходит. Немедленно остановите публикацию выпусков и удалите доверие старому сертификату на затронутых ПК, даже если текущая версия FlowVPN после этого перестанет запускаться. Не ждите готовности нового пакета. Уберите скомпрометированные Secrets, проверьте изменения в репозитории, workflow и выпусках, замените затронутые GitHub credentials и завершите посторонние сеансы.

Создайте новый ключ в проверенной среде. Сообщите об инциденте и новом SHA-256 через независимый доверенный канал: одного объявления в потенциально захваченном репозитории недостаточно. После проверки среды выпустите обновление с сохранёнными Name/Publisher и новой версией по процедуре выше. Если на ПК уже установлена посторонняя сборка, сначала требуется разбор инцидента; обычное обновление не является гарантией очистки.

Удаление доверия и замена сертификата **не обезвреживают уже выполненный вредоносный код**, не закрывают украденные сеансы и не отменяют утечку данных. Временная метка подтверждает время подписи, но не делает подпись с украденным ключом безопасной.

## Как удалить только нужное доверие

В PowerShell от администратора вставьте **SHA-256 старого публичного сертификата**. Не ищите сертификат только по `CN=FlowVPN`: при ротации старый и новый имеют одинаковый Subject.

```powershell
$oldSha256 = 'ВСТАВЬТЕ_64_ШЕСТНАДЦАТЕРИЧНЫХ_СИМВОЛА'
if ($oldSha256 -notmatch '\A[0-9a-fA-F]{64}\z') { throw 'Укажите точный SHA-256 старого сертификата.' }
$sha = [Security.Cryptography.SHA256]::Create()
try {
    $certMatches = @(Get-ChildItem Cert:\LocalMachine\TrustedPeople | Where-Object {
        [BitConverter]::ToString($sha.ComputeHash($_.RawData)).Replace('-', '') -ceq $oldSha256.ToUpperInvariant()
    })
} finally { $sha.Dispose() }
if ($certMatches.Count -ne 1) { throw 'Нужен ровно один сертификат с этим SHA-256; ничего не удалено.' }
$certMatches | Format-List Subject, NotAfter, Thumbprint
Remove-Item -LiteralPath ('Cert:\LocalMachine\TrustedPeople\' + $certMatches[0].Thumbprint) -Confirm
```

Команда не затрагивает корневые CA и просит подтверждение. Если сертификат ранее добавляли вручную в другие хранилища, их нужно отдельно проверить по тому же точному SHA-256.

## Если меняется Publisher

Изменение Subject/Publisher обычно меняет идентичность пакета. Для сохранения идентичности при таком переходе Windows 11 начиная с build 22000 предлагает **MSIX Persistent Identity**: связь издателей оформляется XML/CAT, причём CAT подписывается старым ключом заранее. Старый сертификат должен оставаться доступным и доверенным согласно условиям Microsoft. В FlowVPN этот механизм не реализован и не является восстановлением после компрометации: он опирается на старое доверие и не помогает получить уже потерянный ключ. [MSIX Persistent Identity](https://learn.microsoft.com/en-us/windows/msix/package/persistent-identity).
