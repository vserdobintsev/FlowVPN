FlowVPN — общая модель приложений и расширений

В готовых наборах приложение может содержать расширения. Для перехода
внутрь используется карточка приложения; назад возвращает кнопка со
стрелкой. Выбор сохраняется при переходах и поиске. Поиск находит также
вложенные расширения и показывает название основного приложения.

VS Code — первый заполненный пример: внутри доступны Kilo Code и Codex.
Тот же механизм описывает VS Code Insiders, Cursor и Windsurf; компоненты
предлагаются только при обнаружении на компьютере. Другим программам
не нужна специальная ветка кода: отношения задаются ParentId в каталоге.
Циклы, повторяющиеся идентификаторы и отсутствующие родители отклоняются.

Основное приложение и расширение выбираются независимо. Для Codex
обнаруживаются его собственные процессы в каталоге расширения, включая
встроенные инструменты. Выбор одного расширения не выбирает весь VS Code.
Общий процесс основного приложения может обслуживать другие расширения:
это поясняется в раскрытой карточке основного приложения.

Что унифицировано
1. PresetHierarchy и PresetBrowser: отношения и навигация без названий
   конкретных программ в логике интерфейса.
2. AppPresets.json: расположения, родительское приложение, роли компонентов,
   значки профилей, набор по умолчанию и создание отдельного профиля.
3. InstalledAppLocations: поиск произвольного MSIX по имени пакета из
   каталога, включая установку на другом диске.
4. PresetDiscovery: App Paths Windows, проверка продукта, регистрация
   установки, PATH и ограниченные шаблоны каталогов. Отдельная ветка
   для Яндекса заменена параметрами обычного компонента.
5. PresetProfileFactory: начальные профили по данным каталога и источникам.
   Названия не угадываются по Codex/Telegram/Outline; существующие имена
   и правила пользователя сохраняются. Правила разных профилей не имеют
   общей изменяемой ссылки.
6. Значок профиля берётся из метаданных набора, а не из проверки названия
   профиля на слова «Codex», «Яндекс» или «Outline».
7. Одинаковые геометрия карточки и колонки для найденных и ненайденных
   приложений. Внутренний визуальный тест сравнивает координаты значков
   и заголовков, а не только отсутствие выхода за границы окна.

Сохранённые правила Kilo
Предусмотрен перенос старых групп по точному пути/выражению. Меняются
название и группировка; само выражение сетевого правила не расширяется.
В профиле дочерние наборы названы «Codex · VS Code», «Kilo Code · VS Code»,
чтобы не путать их с отдельными настольными приложениями.

Границы
OpenVPN и Outline действительно имеют разные форматы и возможности;
их специфичные преобразования остаются в сетевом слое. Это осмысленная
зависимость, скрывать её за универсальным строковым конфигом не нужно.
WinUI, получение значков Windows, DPAPI и запуск VPN также имеют свои
границы. Старый WinForms-интерфейс и резервное создание профилей удалены. Используется единый каталог приложений.
Рабочий MSIX запускает отдельный привилегированный процесс управления VPN
через проверяемый локальный IPC. Интерфейс не повышается. Переносимая сборка
и Preview не запускают брокер; они предназначены для разработки и проверки.

Проверки
Искусственное приложение Player с расширением Addon проверяет механизм
без зависимости от установленных программ. Дополнительно проверяются
циклы, поиск вложенных элементов, сохранение выбора, независимость
правил профилей, миграция старой группы и границы процессов Codex.
Сетевое подключение новым GUI во время этих проверок не запускается.

Сведения о расширении сверены с локально установленным пакетом
openai.chatgpt и официальной документацией OpenAI:
https://learn.chatgpt.com/docs/codex/ide
