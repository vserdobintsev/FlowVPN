FlowVPN — структура компонентов и обновлений
Рабочая версия: 1.4.1, 6 ноября 2026

Приложения
AppPresets.json описывает приложения, их расширения через ParentId и компоненты.
Роли: application (приложение), engine (движок), extension (расширение
приложения), shared-service (общая служба). Название роли не зависит
от того, является основное приложение редактором, браузером или чем-то ещё.
Роль отвечает за смысл и представление; FileOnly/Locations — за границы
сетевого правила. Роль «расширение» сама по себе не обещает изоляцию
расширения, работающего внутри общего процесса.

PresetDiscovery — чтение регистрации Windows, PATH, стандартных папок
и ограниченных шаблонов каталогов. Программы при обнаружении не запускаются.
Сначала проверяется реальное наличие EXE. RequiresAnyFile связывает
дополнительный компонент с установленным приложением/расширением.
Разные способы обнаружить один EXE объединяются. Наличие папки без
исполняемого файла не считается установленным приложением.

AppPresets — формирование найденных наборов и метаданных правил.
ApplicationSelection — независимый от WinUI выбор компонентов. Поиск,
фильтр и перерисовка не меняют выбор. Перед сохранением выполняется
повторное обнаружение: исчезнувший компонент не добавляется.
ApplicationGroups — объединение компонентов в одну карточку профиля
и распознавание старых правил по точному пути/шаблону.
ComponentRoles/ComponentPresentation — общие подписи, значки, цвета
и пояснения области действия в выборе приложений и карточке профиля.
ConfigBuilder получает прежние process_path_regex; новые метаданные
не меняют смысл уже сохранённых сетевых правил.

Kilo Code: отдельный kilo.exe внутри расширения предлагается в разделе его основного приложения.
Весь VS Code/Cursor/Windsurf — отдельный набор на странице основного приложения,
выбираемый независимо от расширений. Если запрос выполняет общий процесс основного
приложения, sing-box не сможет выделить только одно его расширение.
OpenCode: настольное приложение и CLI — разные компоненты. Общие node.exe,
PowerShell и терминал целиком не включаются.
NVIDIA App: собственная папка и отдельный nvcontainer.exe. Для контейнера
явно указано, что он общий и правило затронет другие его функции.

Обновления
engine.lock.json фиксирует версию sing-box, SHA-256 официального архива,
самого EXE и libcronet.dll. Новая версия движка входит в новый выпуск
FlowVPN только после проверки конфигураций. База IP обновляется отдельно.
UpdateProtocol — чистая проверка метаданных, версий и идентичности пакета.
UpdateTransport — ограниченные HTTPS-загрузки, проверка SHA-256,
очистка повреждённого кэша, ограничение истории и резервные копии.
UpdatesPage — состояние WinUI и обращение к штатному Windows Deployment API.
Windows проверяет настоящую подпись и доверие издателю при подготовке MSIX.
Предпросмотр и переносимая версия не вызывают установку обновления.
Пакеты другой архитектуры/идентичности/издателя и откаты отклоняются.

Каналы stable/preview имеют разные package identity и отдельные настройки.
Переход между ними — отдельная установка, а не незаметная смена пакета.
UpdateChannels.json пока содержит пустые URL: доставки с сервера ещё нет.
App Installer проверяет публикацию при запуске и фоновым механизмом Windows.
Встроенная проверка при открытом FlowVPN независима от механизма Windows.

Перед выпуском
Build-MSIX.ps1 сверяет движок с lock-файлом, запускает проверки протокола
обновлений и 12 сочетаний OpenVPN/Outline, режима и общей базы; отдельно
проверяет запуск DNS без TUN, слушателей и соединения с VPN.
По умолчанию собирается рабочий пакет с включённым VPN. Параметр -Preview
создаёт отдельный пакет, в котором VPN отключён на уровне сборки.
Основной способ поставки — установка подписанного MSIX. Запуск из bin/Release
с --preview используется для разработческой проверки интерфейса. Сборочные
проверки не подключают туннель, не устанавливают MSIX и не добавляют доверие сертификату.
New-UpdateFeed.ps1 формирует latest.json и .appinstaller для HTTPS-хостинга.
New-GitHubReleaseFeed.ps1 готовит FlowVPN-stable.json и FlowVPN.appinstaller
для GitHub Releases с версионной ссылкой на MSIX.
Get-PinnedCore.ps1 готовит только закреплённые сборочные файлы.
Watch-SingBox.ps1 сообщает о новом upstream-релизе, но не заменяет движок.
Файлы *.yml.example — шаблоны GitHub Actions. В подготовленном репозитории
workflow размещаются в .github/workflows; запуск на GitHub требует публикации
репозитория и настройки параметров выпуска.
Release workflow подписывает постоянным собственным сертификатом CN=FlowVPN.
Публичный CER закреплён в Assets/FlowVPN.cer; PFX и пароль передаются только
через Secrets environment release. Проверяются совпадение сертификата,
идентичность MSIX и временная метка. Установщик запрашивает согласие перед
первым добавлением CER в LocalMachine/TrustedPeople; пакет устанавливается
для исходного пользователя. При обновлении тем же сертификатом повторного
доверия не требуется. Параметры GitHub и порядок выпуска описаны в README.md.
Import-FlowVPNSettings.ps1 переносит настройки и проверенный кэш отдельно от
пакета после установки, до первого запуска. Существующие настройки не заменяет.

Что остаётся отдельным этапом
Реальная установка и обновление MSIX после разрешения пользователя;
проверка на другом физическом ПК и публикация канала обновлений.
Рабочий MSIX поддерживает запрос повышения при подключении. Сейчас
повышается весь интерфейс; выделение минимального брокера с проверяемым IPC
остаётся задачей разделения привилегий. Системная служба не устанавливается.
Обнаружение нестандартных portable/WSL-установок и общих runtime-процессов
может требовать ручного правила или настройки прокси самого приложения.

Описание модели приложений: см. APPLICATION-ARCHITECTURE.txt.
