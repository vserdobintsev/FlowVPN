# Сопровождение проекта

Основной исходник проекта — этот репозиторий с каталогом `src/FlowVPN.WinUI`. Локальные копии из рабочих папок и старых архивов не синхронизируются поверх него: это может уничтожить более новые изменения. Собственные workflows сборки и выпуска находятся в `.github/workflows`. CodeQL работает отдельно через default setup в настройках GitHub; его конфигурация не представлена YAML-файлом в репозитории.

## Небольшие изменения

1. Создайте английскую ветку, например `fix/profile-icon-theme` или `docs/installation-guide`.
2. Измените код и нужную документацию; добавьте регрессионную проверку, если исправляете ошибку поведения.
3. Выполните [проверки разработки](DEVELOPMENT.md) и откройте PR с английским Conventional Commit в заголовке.
4. Дождитесь CI, проверьте diff и обсуждения, затем выполните squash merge. Итоговый заголовок и тело коммита должны быть на английском: GitHub подставляет заголовок PR и по умолчанию оставляет тело пустым. Не копируйте туда русское описание PR; для пояснения передайте отдельное английское сообщение.

Описание PR и пользовательская документация пишутся на русском. Не переписывайте всё форматирование рядом с небольшой правкой. Новые зависимости должны иметь понятную пользу и совместимую лицензию. Для чисто текстовых правок отдельные тесты реализации не нужны.

## Зависимости и движок

Проверяйте PR Dependabot, изменённые разрешения и provenance новых action-коммитов. Для NuGet обновляйте проект и `packages.lock.json` вместе; обычная сборка использует locked restore. sing-box меняется через `engine.lock.json` после проверки конфигураций, API, нативных библиотек и условий распространения. Номер движка сам по себе не доказывает его совместимость.

Не включайте автоматическую установку непроверенной версии движка на компьютерах пользователей. Мониторинг новых выпусков помогает заметить обновление, но не заменяет проверку и новый выпуск FlowVPN.

## Выпуск

Следуйте [RELEASING.md](RELEASING.md). Перед первым стабильным выпуском завершите проверки MSIX/UAC на чистой Windows и сетевую матрицу из [SECURITY.md](../SECURITY.md). Указывайте реальные результаты, не превращая локальный self-test в заявление о независимом аудите.

Ведите [CHANGELOG.md](../CHANGELOG.md) на русском. Тег создаётся после проверки версий, а подписанный workflow по умолчанию готовит черновик. Опубликованную версию не переписывают: исправление получает новый номер.

## Обращения и уязвимости

Не требуйте от пользователей VPN-ключи и полный runtime-конфиг. Для обычной ошибки нужны версия приложения, Windows, воспроизведение и обезличенные сведения. Чувствительные сообщения направляйте через [непубличный канал](../SECURITY.md). Не обещайте срок исправления, пока он не подтверждён.

Просматривайте новые результаты CodeQL в Security → Code scanning и проверяйте, какой коммит и ветку они описывают. Уровень `critical` или `high` относится к правилу анализа и требует проверки реального потока данных; наличие `ArgumentList` или локального источника само по себе не закрывает вопрос доверия к пути. Исправление подтверждается повторным анализом; ручное закрытие ради зелёного статуса не используется. Порядок разбора и исходный снимок — в [SECURITY-REVIEW.md](SECURITY-REVIEW.md).

При компрометации ключа подписи используйте [SIGNING-RECOVERY.md](../src/FlowVPN.WinUI/Distribution/SIGNING-RECOVERY.md). Резервная копия PFX и пароля хранится вне репозитория; GitHub Secrets и DPAPI-файл на одном компьютере не заменяют независимую резервную копию.
