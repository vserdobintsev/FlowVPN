# Необязательный транспортный модуль Outline

[← Архитектура](ARCHITECTURE.md) · [Разработка](DEVELOPMENT.md) · [Безопасность](../SECURITY.md)

**Статус: планируется; модуль ещё не реализован.** Решение согласовано 7 ноября 2026 года. Документ описывает направление разработки, а не доступные функции. Готового адаптера, загрузчика и кнопки установки пока нет; непустой `prefix` по-прежнему отклоняется при импорте.

## Задача и решение

Некоторые ключи Outline используют `prefix` — маскировку первых байтов соединения. Sing-box не поддерживает этот параметр; upstream-запрос закрыт как [не планируемый к реализации](https://github.com/SagerNet/sing-box/issues/3230). Удалять параметр молча нельзя: ключ может перестать работать в сети пользователя.

Планируется отдельный нативный адаптер на [Outline SDK](https://github.com/OutlineFoundation/outline-sdk). Исходники останутся в этом репозитории, а исполняемый файл будет отдельным артефактом выпуска, который пользователь сможет скачать из FlowVPN при необходимости. Устанавливать Go или приложение Outline пользователю не потребуется. Sing-box не заменяется и остаётся единственным владельцем TUN, DNS и правил маршрутизации.

```text
Приложения → sing-box: TUN и правила → локальный SOCKS5 → адаптер Outline → сервер
```

SDK предоставляет транспортные примитивы, но готовый защищённый SOCKS-сервер для этой схемы не подтверждён. Его обработчик, аутентификацию и управление UDP-сеансами необходимо реализовать или выбрать и проверить отдельно. Универсальный механизм загрузки сторонних плагинов не нужен.

## Подключения и возможности

Вместо распознавания текста исключения импорт должен возвращать типизированный результат: корректное подключение, недостающая возможность либо недопустимый формат. Например, `RequiresCapability` с идентификатором `outline.ss-prefix.tcp.v1`. Проверка всех полей предшествует предложению установки. Неизвестные параметры и расширенные транспорты не становятся поддерживаемыми автоматически.

Параметры адаптера хранятся в отдельном типизированном дескрипторе с версией схемы внутри `VpnSource`, под существующей защитой DPAPI. `ConnectionJson` сохраняет назначение конфигурации sing-box; добавлять туда игнорируемый движком `prefix` нельзя. Доступность модуля вычисляется заново, а не хранится флагом «установлен навсегда».

Тип результата необходимо сохранить через `Importers.Installed`, `ConnectionInput` и интерфейс пакетного импорта. `VpnEngine.Connect` повторно проверяет возможности после обновления `ssconf://` и заменяет весь транспортный дескриптор. Статический fingerprint учитывает prefix и его семантику; динамическое подключение сохраняет идентичность по исходному ключу.

По [документации Outline](https://developer.getoutline.org/vpn/advanced/prefixing/) prefix задаёт начало соли Shadowsocks: символы U+0000–U+00FF соответствуют отдельным байтам, а не UTF-8-последовательностям. Рекомендован предел 16 байт; проверка также должна учитывать размер соли выбранного шифра и сохранять достаточную случайную часть. У статического `ss://` prefix применяется только к TCP; другие формы конфигурации могут задавать TCP и UDP отдельно. Набор возможностей адаптера должен явно учитывать формат, протокол и шифр.

## Поставка и граница доверия

Доверенный каталог компонентов включается в подписанный MSIX. Для каждого артефакта он фиксирует идентификатор, версию, версию IPC, совместимость с FlowVPN и Windows, архитектуру, возможности, HTTPS-адрес, размер, SHA-256 и имя исполняемого файла. Версии SDK, Go и зависимостей закрепляются при сборке; лицензии и уведомления включаются в поставку. SDK распространяется под Apache-2.0.

Самоподписанный MSIX требует предварительного доверия сертификату издателя. Проверка пакета защищает встроенный каталог, но не удостоверяет произвольный скачанный exe. Хеш из отдельного неподписанного JSON рядом с файлом не заменяет закрепление в MSIX. Обновление разрешённой версии модуля проходит проверку совместимости и поставляется с обновлением FlowVPN.

Загрузчик работает без повышения прав: ограничивает размер, пишет временный файл, сверяет размер и хеш, затем атомарно размещает его в версионной папке данных. Перед запуском повторно проверяются файл и путь, с защитой от подмены между проверкой и запуском. Нельзя менять `core/`, `engine.lock.json` или запускать скачанный код через повышенный брокер.

## Запуск и интерфейс

Адаптер работает с обычными правами только во время нужного подключения. Он занимает случайный loopback-порт до объявления готовности; параметры и временные секреты получает через проверяемый IPC, а не CLI. SOCKS5 требует аутентификацию, UDP association привязывается к авторизованной управляющей сессии. Журналы ограничены и не содержат ключей.

Брокер принимает только строго описанную локальную транспортную сессию и сам собирает SOCKS outbound на `127.0.0.1`. Контракт не допускает путь к exe, произвольный внешний прокси или готовый конфиг от модуля. Физический интерфейс и готовность адаптера согласуются до включения TUN: его внешний трафик не должен попадать обратно в туннель. Остановка и аварии входят в общий жизненный цикл сеанса; автоматической подмены VPN-маршрута на `direct` нет. Это само по себе не обещает kill switch после остановки TUN.

Сообщение пользователю:

> Этот ключ Outline использует дополнительную маскировку соединения. Для него нужен модуль Outline. Он загрузится отдельно и будет запускаться только для таких подключений.

Кнопка «Скачать модуль · … МБ» появляется только при наличии совместимого опубликованного артефакта в доверенном каталоге. До этого показывается объяснение ограничения без неработающей кнопки. Загрузка имеет прогресс и отмену; после проверки доступно продолжение добавления подключения. Уже полученные параметры повторно проверяются без ненужного запроса к провайдеру.

## Приёмка прототипа до выпуска

1. Локальный тестовый сервер подтверждает TCP/UDP, байты prefix, шифры и различия форматов ключей; неподдерживаемые варианты отклоняются явно.
2. Проверены SOCKS-аутентификация и UDP association: постороннее соединение не может пользоваться локальным relay.
3. Проверены отмена, потеря сети, падение каждого процесса и завершение родителя; нет оставшихся процессов и скрытого обхода выбранного транспорта.
4. Проверены IPv4/IPv6, DNS и физический интерфейс при работающем TUN; нет циклической маршрутизации.
5. Подмена файлов, неверный хеш, прерванная загрузка, несовместимые архитектура и IPC не приводят к запуску.
6. Измерены размер exe, прирост сжатого MSIX, память и пропускная способность. Численные обещания до замеров не даются.
7. Чистая поддерживаемая Windows проходит установку MSIX и загрузку компонента без Go и Outline. Отдельно проверены обновление и удаление модуля при сохранённых подключениях.

До этой приёмки документация и интерфейс не должны обещать поддержку ключей с prefix.
