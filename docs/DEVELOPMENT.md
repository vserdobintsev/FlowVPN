# Разработка и проверки

[← К README](../README.md) · [Архитектура](ARCHITECTURE.md) · [Выпуск версии](RELEASING.md)

## Окружение

Сборка выполняется на Windows x64. Нужны Git, PowerShell 7.4+ и .NET SDK, закреплённый в [`global.json`](../global.json). Текущий проект использует .NET 10 и WinUI 3; версии NuGet хранятся в [`packages.lock.json`](../src/FlowVPN.WinUI/packages.lock.json).

Целевая версия Windows SDK указана в [`FlowVPN.WinUI.csproj`](../src/FlowVPN.WinUI/FlowVPN.WinUI.csproj). SDK BuildTools приходит через NuGet. Исходники не включают движок, личные VPN-профили, закрытый ключ подписи и сборочные каталоги.

## Первая сборка

В PowerShell из корня репозитория:

```powershell
dotnet restore src/FlowVPN.WinUI/FlowVPN.WinUI.csproj --locked-mode
./src/FlowVPN.WinUI/Distribution/Get-PinnedCore.ps1 -Destination ./outputs/FlowVPN/core
./src/FlowVPN.WinUI/Build-MSIX.ps1 -Unsigned
```

`Get-PinnedCore.ps1` загружает официальный архив закреплённой версии sing-box и проверяет SHA-256 архива и файлов по [`engine.lock.json`](../src/FlowVPN.WinUI/engine.lock.json). Движок не устанавливается в систему. Для предварительно скачанного архива предусмотрен параметр `-ArchivePath`.

`Build-MSIX.ps1` сначала собирает приложение и выполняет изолированные проверки, затем формирует рабочий MSIX. Результат находится в `outputs/FlowVPN-MSIX`. Параметр `-Unsigned` создаёт пакет для проверки сборки: он не предназначен для обычной пользовательской установки.

Сборка не импортирует сертификаты, не устанавливает пакет, не включает автозапуск и не поднимает TUN. Проверки локального API используют тестовый sing-box без внешнего VPN-подключения.

## Конфигурации

| Конфигурация | Назначение |
| --- | --- |
| `Release` | Запуск из каталога сборки для разработки и диагностики |
| `MsixRelease` | Рабочий MSIX с доступным подключением VPN |
| `MsixPreview` | Отдельный MSIX, в котором подключение VPN отключено при компиляции |

Для тестового MSIX:

```powershell
./src/FlowVPN.WinUI/Build-MSIX.ps1 -Preview -Unsigned
```

Рабочая редакция и Preview имеют разные идентичности пакета. Они не заменяют друг друга при обновлении.

## Проверка интерфейса без подключения

После первой сборки откройте приложение с явным `--preview`:

```powershell
./src/FlowVPN.WinUI/bin/Release/net10.0-windows10.0.26100.0/win-x64/FlowVPN.exe `
  --preview --root ./outputs/FlowVPN
```

В этом режиме подключение VPN заблокировано. Данные проверки сохраняются в указанном `--root`; используйте отдельный каталог репозитория, а не папку действующего VPN. Файл `preview-only.flag` в корне разработческой копии также включает предпросмотр.

`--root` предназначен для запуска из каталога сборки и диагностики. Установленный MSIX этот параметр отклоняет: движок выбирается из каталога установленного пакета. В разработческой копии движок должен лежать на локальном несъёмном диске. Его файлы и цепочка каталогов до `core` не должны содержать reparse points — в том числе junction, symlink, точки монтирования или каталоги OneDrive с этим атрибутом. Для разработки используйте обычную локальную папку. Это ограничение пути движка не распространяется автоматически на все пользовательские данные.

Встроенные режимы проверки:

| Аргумент | Что проверяет |
| --- | --- |
| `--release-self-test` | Конфигурации, обновления, функции приложения и локальный API движка |
| `--visual-test` | Геометрию интерфейса и сценарии отображения; сохраняет PNG |
| `--performance-test` | Работу алгоритмов доменных правил |

Передавайте `--root` с отдельной тестовой папкой и подготовленным `core`. Штатный `Build-MSIX.ps1` создаёт изолированную папку сам и ждёт завершения самопроверок. Для обычного изменения используйте этот путь; специальные режимы нужны для адресного исследования.

## Проверки перед pull request

1. Выполните `pwsh ./tools/Test-Repository.ps1`, затем сборку и проверки, соответствующие изменению.
2. Для сетевых правил проверьте оба источника и затронутые режимы профиля; для интерфейса — темы, узкое окно и навигацию клавиатурой.
3. Проверьте публичную границу исходников:

   ```powershell
   ./src/FlowVPN.WinUI/Distribution/Test-Source.ps1 -Root .
   ```

4. Укажите в PR, что проверено автоматически и что проверено вручную. Не заменяйте испытания настоящего туннеля результатом `sing-box check`.

`Test-Source.ps1` ищет известные типы закрытых файлов и шаблоны секретов. Это вспомогательная проверка, а не доказательство отсутствия чувствительных данных. Перед добавлением файлов просматривайте `git diff --cached`.

Сборочные проверки хранят отчёты JSON в `outputs/FlowVPN-MSIX`. Они не требуют личных профилей OpenVPN/Outline. Файлы `*Checks.cs` содержат исполняемые проверки в самом проекте; отдельный тестовый фреймворк сейчас не используется.

Для защиты основной ветки используются проверки **`Build (Release)`**, **`Build (Preview)`** и **`Conventional title`**. Последняя проверяет формат английского заголовка PR; после squash merge этот заголовок становится сообщением коммита. Зелёный CI подтверждает только выполненные сценарии и не заменяет ручную проверку установки и настоящего туннеля.

Для C# дополнительно включён CodeQL через GitHub default setup: набор Extended и модель угроз `remote_and_local`, с еженедельным запуском. Его результаты находятся в Security → Code scanning; отдельный CodeQL YAML в репозитории не требуется. Это отдельный анализ исходников, а не замена сборке, NuGet audit или проверке поведения. Перед исправлением предупреждения изучите все показанные потоки данных и условия выполнения. [Как разбираются результаты](SECURITY-REVIEW.md).

## Зависимости и движок

NuGet restore работает с lock-файлом. Изменение пакета сопровождается осознанным обновлением lock-файла и проверкой транзитивных зависимостей. NuGet audit настроен прерывать сборку при известных предупреждениях уязвимостей `NU1901`–`NU1904`.

Workflow [dependency-audit.yml](../.github/workflows/dependency-audit.yml) дополнительно проверяет закреплённые зависимости каждый понедельник в 09:35 по Москве и по ручному запуску. Он выполняет только restore с аудитом, без сборки MSIX, установки и подключения VPN. Неудачное получение данных аудита также завершает проверку ошибкой. Dependabot отдельно предлагает обновления GitHub Actions; автоматического слияния таких PR нет.

Обновление sing-box требует изменения версии и контрольных сумм в `engine.lock.json`, а затем проверки конфигураций и интеграции. Скрипт `Watch-SingBox.ps1` сообщает о новом upstream-выпуске и не заменяет движок автоматически.

NuGet audit не покрывает Go-зависимости sing-box, libcronet и все поставляемые нативные библиотеки. Их аудит и обязательства распространения рассматриваются отдельно; см. [SECURITY.md](../SECURITY.md) и [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md).

## Стиль изменений

Правила коммитов, веток, обзора изменений и коммуникации находятся в [CONTRIBUTING.md](../CONTRIBUTING.md). Примеры Conventional Commits:

```text
fix(routing): preserve domain exceptions when the base is disabled
feat(profiles): add searchable profile icons
docs: clarify certificate renewal
```

Небольшой PR должен решать одну понятную задачу. Изменения данных, безопасности и маршрутизации требуют проверки поведения; косметическая правка текста не требует нового набора тестов, повторяющего реализацию.
