# Настройки GitHub

Файлы `.github/repository-settings.json` и `.github/labels.json` описывают настройки проекта. GitHub сам не применяет эти JSON: ими управляет [Configure-Repository.ps1](../tools/Configure-Repository.ps1).

Сначала создайте публичный репозиторий, отправьте первый коммит и дождитесь успешных проверок. Нужны GitHub CLI, PowerShell 7.4+ и права администратора репозитория:

```powershell
./tools/Configure-Repository.ps1 -Repository OWNER/FlowVPN
./tools/Configure-Repository.ps1 -Repository OWNER/FlowVPN -Apply
```

Первый вызов показывает локальный план, второй применяет его через GitHub API. `-Apply -WhatIf` проверяет доступ и показывает действие без записи. Скрипт не создаёт репозиторий, не загружает ключ подписи и не публикует выпуск. Чужие labels и rulesets не удаляются; обновляются только перечисленные метки и два именованных ruleset FlowVPN.

## Работа с изменениями

- Основная ветка — `main`. Изменения проходят через pull request и squash merge.
- Заголовок PR становится заголовком коммита: английский Conventional Commit. Тело squash-коммита по умолчанию пустое (`BLANK`), поэтому русское описание PR не попадает в историю. Вручную добавленное тело тоже пишется на английском.
- Обязательные проверки: `Build (Release)`, `Build (Preview)`, `Conventional title`. Для статусов закреплено приложение GitHub Actions, поэтому одноимённый статус другого приложения их не заменяет.
- Перед слиянием ветка должна соответствовать актуальной `main`, а обсуждения должны быть разрешены.
- Force push и удаление `main` запрещены. Для тегов `v*` запрещены переписывание и удаление.
- После слияния рабочая ветка удаляется автоматически. Долгоживущая `develop` не нужна.

Сейчас проект сопровождает один разработчик: PR обязателен, но чужое одобрение не требуется. Это позволяет владельцу сопровождать проект без фиктивного второго ревьюера. При появлении команды установите минимум одно одобрение и, при необходимости, обязательное ревью владельцев кода. `CODEOWNERS` сам по себе не делает одобрение обязательным.

## Безопасность и выпуск

По умолчанию `GITHUB_TOKEN` имеет доступ только на чтение. Actions не могут одобрять PR. Разрешены официальные действия GitHub с закреплением по полному SHA. Дополнительные разрешения задаются явно в нужном job.

Включаются Dependabot alerts и security updates, secret scanning, push protection и Private Vulnerability Reporting. Обновления GitHub Actions поступают отдельными PR через Dependabot; автоматического слияния нет. NuGet остаётся под locked restore и NuGet audit: обновление требует пересоздания lock-файла и проверки совместимости.

CodeQL включён в GitHub через **default setup**: язык C#, набор **Extended** (`extended` в API), модель угроз **`remote_and_local`**, еженедельный запуск. Его конфигурация хранится в настройках сервиса, поэтому отдельного CodeQL YAML в `.github/workflows` нет. Это не означает, что анализ выключен. Скрипт `Configure-Repository.ps1` не заменяет настройку CodeQL; при переносе проекта в другой репозиторий её необходимо включить и проверить отдельно. Снимок первого анализа и правила разбора результатов — в [SECURITY-REVIEW.md](SECURITY-REVIEW.md).

Environment `release` требует ручного разрешения владельца и допускает запуск только из основной ветки `main` по явной branch policy. Workflow запускается из `main`, а тег нужного выпуска указывается параметром. Собственное одобрение разрешено для единственного сопровождающего. Секреты `PFX_BASE64` и `PFX_PASSWORD` добавляются отдельно; скрипт их не читает и не загружает. [Порядок выпуска](RELEASING.md).

Issues используются для воспроизводимых ошибок и предложений, Discussions — для вопросов. Wiki и отдельные GitHub Projects выключены: документация и её история находятся рядом с кодом.

Применение может частично завершиться при отказе API или ограничениях аккаунта. Ошибка не скрывается; проверьте уже применённые настройки и повторите вызов после устранения причины. Сам файл плана не доказывает, что настройки активны: состояние нужно проверить в GitHub Settings.
