# Выпуск версии

[← К README](../README.md) · [Разработка](DEVELOPMENT.md) · [Безопасность](../SECURITY.md)

Основной путь поставки — подписанный MSIX с движком, проверенным для этой версии FlowVPN. Публикацию выполняет [release workflow](../.github/workflows/release.yml); по умолчанию он создаёт **черновик** GitHub Release.

Сборка 1.4.1 подготовлена локально. Настройка GitHub environment, запуск workflow и испытание установки/обновления на чистой Windows являются отдельными шагами. Наличие workflow в репозитории само по себе не означает, что эти действия уже выполнены.

## Перед первым выпуском

1. Настройте права репозитория и защиту основной ветки. Выпуск должен ссылаться на проверенный коммит и существующий версионный тег.
2. Создайте GitHub environment `release`. Ограничьте доступ к нему ветками или тегами выпуска и настройте доступные для репозитория правила одобрения.
3. Сохраните закрытый ключ и пароль как Secrets этого environment. Открытый сертификат [`Assets/FlowVPN.cer`](../src/FlowVPN.WinUI/Assets/FlowVPN.cer) остаётся в исходниках.
4. Подготовьте защищённую резервную копию **PFX и пароля** вне GitHub. Файл `password.dpapi`, привязанный к конкретной учётной записи Windows, не заменяет переносимую резервную копию пароля.
5. Проверьте комплект лицензий и соответствующих исходников сторонних компонентов по [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md).

| Где задать | Имя | Значение |
| --- | --- | --- |
| Environment `release` → Secret | `PFX_BASE64` | PFX с закрытым ключом выпуска, закодированный в Base64 |
| Environment `release` → Secret | `PFX_PASSWORD` | Пароль PFX |
| Repository variable, необязательно | `FLOWVPN_TIMESTAMP_URL` | Сервер временных меток RFC 3161; по умолчанию `http://timestamp.digicert.com` |

PFX, пароль и их Base64-представления не должны попадать в файлы репозитория, issues, PR, журналы или артефакты. Workflow сверяет сертификат PFX с открытым CER до подписания. Совпадения одного `Subject` недостаточно: проверяется SHA-256 сертификата.

## Подготовка версии

Версия должна совпадать в проекте, MSIX-манифесте и теге:

| Место | Пример |
| --- | --- |
| `FlowVPN.WinUI.csproj` | `1.4.1` |
| `Package.appxmanifest` | `1.4.1.0` |
| Git tag | `v1.4.1` |

Если меняется Preview, обновите и его манифест. При обновлении sing-box сначала измените `engine.lock.json`, проверьте совместимость и зафиксируйте соответствующие исходники и лицензии поставляемой версии.

Обновите [CHANGELOG.md](../CHANGELOG.md), статус в README и инструкции, затронутые изменением. Укажите исправленные ошибки и известные ограничения. Не описывайте проверки, которые ещё не выполнялись.

После проверки PR и CI создайте тег на выбранном коммите. Пример команды:

```powershell
git tag -a v1.4.1 -m "Release FlowVPN 1.4.1"
git push origin v1.4.1
```

Опубликованный тег и файлы выпуска не заменяются. Исправление опубликованного бинарного пакета получает новую версию.

## Сборка и подпись

В GitHub Actions запустите `FlowVPN signed MSIX release` с параметрами:

```text
tag: v1.4.1
publish: false
```

Workflow выполняет следующие этапы:

1. Проверяет соответствие тега версии проекта и манифеста, открытый сертификат и отпечаток в CMD-установщике.
2. Восстанавливает закреплённые зависимости, получает закреплённый движок и собирает рабочий MSIX с изолированными проверками.
3. На отдельном runner получает PFX из environment Secrets, сверяет сертификат и подписывает пакет с временной меткой RFC 3161.
4. Проверяет подписанное содержимое, временно добавляет открытый сертификат в `TrustedPeople` **только одноразового runner** и выполняет полную проверку Windows через SignTool.
5. Формирует метаданные обновления, установочный архив и контрольные суммы. Временное доверие и PFX удаляются.
6. Повторно проверяет, что тег ссылается на исходный коммит, затем создаёт черновик GitHub Release.

Ошибки подписи, временной метки, соответствия сертификата или проверки пакета прерывают выпуск. Повторное создание уже существующего Release отклоняется, его артефакты не перезаписываются.

Параметр `publish: true` предусмотрен для **первого запуска** workflow, если публикация после проверок уже согласована. Для обычной подготовки оставляйте `false`; готовый черновик публикуется вручную через интерфейс GitHub после испытаний. Повторный запуск с `publish: true` не предназначен для публикации существующего черновика.

## Приёмка черновика

Перед публичной публикацией проверьте хотя бы один чистый компьютер или виртуальную машину с поддерживаемой Windows:

- Установку из полного комплекта и соответствие отпечатка CER опубликованному.
- Запуск обычным пользователем, запрос UAC, отказ от UAC и корректное завершение приложения.
- Подключение OpenVPN и Outline, маршруты приложений и доменов, работу общей базы.
- Обрыв сети, восстановление, сон и смену адаптера; наблюдение за состоянием само по себе не является проверкой отсутствия утечек.
- Обновление поверх предыдущей версии с сохранением настроек; отдельную установку Preview без подмены рабочего пакета.
- Работу автозапуска, меню трея, управления на панели задач и удаления MSIX.

Запишите результаты и непроверенные сценарии в описание выпуска. Самопроверки без TUN не заменяют эти испытания.

## Состав выпуска

| Артефакт | Назначение |
| --- | --- |
| `FlowVPN-<version>-x64.msix` | Подписанный пакет |
| `FlowVPN-<version>-win-x64-setup.zip` | MSIX, открытый CER и полный набор установщика |
| `FlowVPN.cer` | Открытый сертификат издателя |
| `FlowVPN-stable.json` | Метаданные встроенного канала обновлений |
| `FlowVPN.appinstaller` | Описание установки и обновлений для Windows App Installer |
| `SHA256SUMS.txt` | Контрольные суммы публичных файлов выпуска |
| `package-checks.json` | Результат структурной проверки пакета |

Архив исходников GitHub определяется тегом. Дополнительно подготовьте необходимые материалы по сторонним компонентам; ссылка на upstream сама по себе не объявляется выполнением всех обязательств распространителя.

## Канал обновлений

При сборке workflow добавляет в `UpdateChannels.json` адрес выбранного репозитория. Для этого проекта стабильный канал после публикации находится по адресам:

```text
https://github.com/vserdobintsev/FlowVPN/releases/latest/download/FlowVPN-stable.json
https://github.com/vserdobintsev/FlowVPN/releases/latest/download/FlowVPN.appinstaller
```

Ссылка на MSIX внутри метаданных привязана к конкретному тегу. Ссылка `latest` используется только для поиска актуальных метаданных. До первого опубликованного выпуска эти адреса не являются работающим каналом доставки.

FlowVPN проверяет HTTPS, версию, идентичность, размер и хеш; доверие подписи устанавливает Windows. Приложение не добавляет новые сертификаты в доверенные автоматически. Ротация или потеря ключа требует [отдельной процедуры](../src/FlowVPN.WinUI/Distribution/SIGNING-RECOVERY.md).
